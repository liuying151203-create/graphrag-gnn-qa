# 系统架构设计

## 目标

本系统旨在构建一个面向科研论文和技术文档的复杂关联知识问答系统，通过 GraphRAG 将向量检索与知识图谱检索结合起来，并进一步使用 GNN 对图谱节点表示进行结构增强。

## 总体流程

```text
用户问题
  -> 查询理解
  -> 向量检索
  -> 实体识别
  -> 图谱遍历
  -> GNN 节点召回
  -> 候选上下文合并
  -> Rerank
  -> LLM 生成答案
  -> 返回答案、来源和图谱路径
```

## 核心模块

### API 层

使用 FastAPI 提供 HTTP 接口，包括健康检查、文档导入、问答和检索调试接口。

### 配置层

通过 `.env` 管理运行配置，包括 LLM、Neo4j、Milvus、Embedding 和检索参数。

### 文档处理层

负责读取 PDF、Markdown、TXT 等文档，完成文本清洗、切分和元数据维护。

### 向量检索层

使用 BGE-m3 生成文本块向量，并将向量写入 Milvus，提供基于语义相似度的 TopK 检索能力。

### 图谱构建层

使用 LLM 从文本块中抽取实体和关系三元组，并写入 Neo4j，形成结构化知识图谱。

### GraphRAG 检索层

结合向量召回结果与 Neo4j 图谱遍历结果，构建更完整的上下文，支持跨文档、多实体、多跳关系查询。

### GNN 表示学习层

从 Neo4j 导出节点和边，将 BGE-m3 节点语义向量作为初始特征，使用 GAT 学习结构感知的节点表示。

### 评估层

通过多跳 QA 测试集评估不同检索策略的准确率、召回率、MRR 和响应延迟。
